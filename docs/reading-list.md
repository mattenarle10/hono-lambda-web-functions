# Reading List Demo

Save a documentation link, find it later, and mark it read. Use Scalar or curl. This is a single-owner learning API, not a multi-user bookmark service.

| Request | Result |
|---|---|
| `POST /bookmarks` | Validate and save a title/URL; return `201` with its ID |
| `GET /bookmarks` | Return up to 20 links and `nextCursor` |
| `PATCH /bookmarks/{id}/read` | Mark an existing link read; missing/expired links return `404` |

All three routes require `Authorization: Bearer <token>`. Health, profile, OpenAPI, and Scalar remain public. URLs are stored as text; the server never fetches a submitted URL.

## Local Demo

1. From the installed repo, start the server with an explicitly local token:

   ```sh
   READING_LIST_MODE=memory DEMO_API_TOKEN=local-demo-only bun run dev
   ```

   Memory mode resets on restart. This token is a localhost example; the cloud deployment generates its own secret. Do not deploy the local token or memory mode.

2. In another terminal, select the local endpoint and token:

   ```sh
   export ENDPOINT_URL=http://127.0.0.1:3000
   export DEMO_API_TOKEN=local-demo-only
   ```

3. Run the three requests below, or open `/scalar`, choose **ReadingListToken**, and enter the token without the `Bearer` prefix.

## Cloud Demo

**Uses billable DynamoDB and Secrets Manager resources.** Deploy with the main README's `cdkd` commands and verify the target identity first.

1. Read `EndpointUrl` and `ReadingListTokenSecretArn` from the scoped state:

   ```sh
   cdkd state show HonoLambdaWebDirectStack \
     --state-prefix hono-web-poc --profile "$AWS_PROFILE"
   export ENDPOINT_URL='https://your-endpoint-domain'
   export READING_LIST_TOKEN_SECRET_ARN='paste-the-output-secret-arn'
   ```

   If `cdkd` is unavailable, use `bunx --no-install cdkd`. Copy your own output values. Do not put resolved state or identifiers into source.

2. Retrieve the generated demo token into your shell variable. This command reads a secret; do not run with shell tracing, echo the value, or share it:

   ```sh
   export DEMO_API_TOKEN="$(aws secretsmanager get-secret-value \
     --secret-id "$READING_LIST_TOKEN_SECRET_ARN" \
     --query SecretString --output text \
     --profile "$AWS_PROFILE" --region "$AWS_REGION")"
   ```

3. Run the workflow below. Afterwards, clear the token variable:

   ```sh
   unset DEMO_API_TOKEN
   ```

## Save, List, Mark Read

1. Save a link. Copy `id` from the response:

   ```sh
   curl --fail-with-body "$ENDPOINT_URL/bookmarks" \
     -H "Authorization: Bearer $DEMO_API_TOKEN" \
     -H 'Content-Type: application/json' \
     --data '{"title":"Hono on Node.js","url":"https://hono.dev/docs/getting-started/nodejs"}'
   ```

2. List links:

   ```sh
   curl --fail-with-body "$ENDPOINT_URL/bookmarks" \
     -H "Authorization: Bearer $DEMO_API_TOKEN"
   ```

   If `nextCursor` is not null, request `/bookmarks?cursor=<nextCursor>` for the next page. Ordering is by ID. Follow the cursor even if an expiry filter produces an empty page.

3. Mark the saved link read:

   ```sh
   export BOOKMARK_ID='paste-the-created-id'
   curl --fail-with-body -X PATCH "$ENDPOINT_URL/bookmarks/$BOOKMARK_ID/read" \
     -H "Authorization: Bearer $DEMO_API_TOKEN"
   ```

   List again to see `status: "read"`. Without a token, all three routes return `401`.

## Where the Data Lives

```txt
Scalar / curl -> Web Function -> Hono validation + token check -> DynamoDB
                                  |
                                  +-> Secrets Manager (cached token, 60 seconds)
```

DynamoDB persists records across requests and execution environments. AWS clients are reused; cloud data and request-specific state are not kept in a shared process map. The runtime role has only `PutItem`, `Query`, and `UpdateItem` for this table and `GetSecretValue` for this secret, plus scoped logging.

Links expire from the API after 24 hours. DynamoDB TTL deletes expired records asynchronously, usually within a few days; TTL is not an immediate physical deletion promise. The list excludes expired records and updates cannot revive them. [AWS TTL guidance](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/TTL.html)

The token is generated by AWS and retrieved at runtime, rather than stored in a revision's environment. Environment variables contain the table name and secret ARN only. [AWS Web Function environment guidance](https://docs.aws.amazon.com/lambda/latest/dg/web-functions-revisions-env-vars.html)

This shared token is a POC shortcut. A real multi-user service needs user authentication, per-user authorization and partitions, abuse controls, and a retention policy appropriate to the data. The disposable table is deleted by app cleanup. Never store your real reading history here.

## Verified in the POC

The Tokyo deployment passed save, list, and mark-read. An independent DynamoDB read confirmed the saved record's read status and expiry. All three operations rejected missing and invalid tokens; invalid input returned `400` and a missing update returned `404`. Original public routes and startup logging also passed.

These are HTTP and database checks. The expanded Scalar operations are present in OpenAPI; a new browser walkthrough and sanitized screenshots are still pending.

## What This Demonstrates

The server awaits a real database operation. While one request waits for DynamoDB, another can use the Node.js event loop within the same Web Function environment. That is the useful workload shape here. It does not establish a billing saving, production capacity, or a latency improvement over API Gateway or ECS.

The [existing benchmarks](../benchmarks/README.md) measured the earlier health-only version, before the reading-list resources and SDK dependencies were added. They are deployment-loop and HTTP observations for that earlier code, not database benchmarks.
